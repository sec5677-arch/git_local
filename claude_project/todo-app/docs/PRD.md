# PRD - Tika: Ticket-based Kanban Board

> 작성일: 2026-08-01
> 프로젝트명: Tika

---

## 1. 제품 개요

### 1.1 개요
Tika는 **티켓 기반 칸반 보드 TODO 앱**이다. 단일 사용자가 할 일을 티켓으로 등록하고, 4개의 고정 컬럼(Backlog → TODO → In Progress → Done) 간 드래그 앤 드롭으로 상태를 관리한다.

### 1.2 핵심 가치
- **단순함**: 필요한 기능만 제공, 빠른 학습 곡선
- **직관성**: 드래그 앤 드롭으로 시각적으로 상태 변경
- **일정 관리**: 시작일/종료일로 작업 시간 관리

### 1.3 목표 사용자
- 개인 개발자/디자이너/기획자
- 소규모 프로젝트 또는 개인 작업 관리
- 복잡한 협업 도구가 필요한 않는 작업 목록 관리

## 3. 사용자 시나리오

### 3.1 할 일 등록
1. 사용자가 "새 티켓" 버튼 클릭
2. 제목, 설명(선택), 일정 정보를 입력
3. 저장 시 티켓이 **Backlog** 컬럼에 추가
4. 피드백: 토스트 메시지 "티켓이 생성되었습니다"

### 3.2 상태 이동 (드래그 앤 드롭)
1. 사용자가 티켓을 드래그
2. 다른 컬럼 위에 드롭 → 상태 변경
3. 필요시 컬럼 내에서 순서 변경
4. 피드백: 이동 직후 즉시 UI 업데이트

### 3.3 티켓 수정
1. 티켓 클릭 또는 수정 아이콘 클릭
2. 모달/패널에서 정보 편집
3. 저장 시 변경사항 반영

### 3.4 티켓 삭제
1. 삭제 아이콘 클릭
2. 확인 다이얼로그 표시
3. 확인 시 티켓 제거, 취소 시 유지

### 3.5 완료 확인
1. 티켓을 Done 칼럼으로 이동하면 완료 처리 (completedAt 자동 기록)
2. Done에서 다른 칼럼으로 되돌리면 completedAt 초기화
3. Done 칼럼에는 완료 후 24시간 이내 티켓만 표시
4. 종료예정일 지난 미완료 티켓은 오버듀 경고 표시

## 4. 핵심 기능 목록

### FR-001: 티켓 생성
- 제목(필수), 설명(선택), 우선순위(LOW/MEDIUM/HIGH), 계획시작일, 계획종료일(선택)
- 기본 상태: Backlog
- 생성 시 position은 해당 칼럼 최솟값 - 1024

### FR-002: 티켓 목록 조회 (보드)
- 컬럼별 티켓 목록 표시 (Backlog / TODO / In Progress / Done)
- 각 티켓에 오버듀(isOverdue) 파생 필드 포함
- 각 칼럼 내 position 오름차순 정렬

### FR-003: 티켓 상세 조회
- 티켓 ID로 전체 정보 조회
- 수정/삭제 버튼 포함

### FR-004: 티켓 수정
- 제목, 설명, 우선순위, 계획시작일, 계획종료일 수정
- 부분 수정(PATCH) 지원
- updatedAt 자동 갱신

### FR-005: 티켓 완료 (완료일 업데이트)
- Done 칼럼으로 이동 시 completedAt = 현재 시각
- Done에서 다른 칼럼으로 이동 시 completedAt = null
- Done 칼럼에는 completedAt 기준 24시간 이내 티켓만 표시

### FR-006: 티켓 삭제
- 영구 삭제 (soft delete 아님)
- 삭제 전 확인 다이얼로그

### FR-007: 상태/순서 변경 (드래그앤드롭)
- 티켓을 다른 칼럼으로 이동
- 같은 칼럼 내에서 순서 변경
- position 재계산 로직: (prev + next) / 2, 간격 부족 시 전체 재정렬
- TODO로 이동 시 startedAt 자동 기록
- Done 이동은 FR-005(완료 처리)를 사용

### FR-008: 오버듀 판정
- 종료예정일(dueDate)이 오늘 이전이고 DONE이 아닌 티켓
- 조회 시 계산되는 파생 필드 (DB 저장 아님)

## 5. 기술 스택

### 5.1 스택 요약

| 영역 | 기술 | 선정 이유 |
|------|------|-----------|
| **Framework** | Next.js 15 (App Router) | 파일 기반 라우팅, SSR/CSR 유연성, Vercel 배포 용이 |
| **Language** | TypeScript (strict) | 타입 안전성, 리팩토링 용이성 |
| **Frontend** | React 19 | 최신 기능(Server Components), 성능 개선 |
| **Styling** | Tailwind CSS 4 | 유틸리티 퍼스트, 빠른 스타일링, 간편한 반응형 |
| **Drag & Drop** | @dnd-kit/core + @dnd-kit/sortable | 접근성 지원, 터치 디바이스 호환,轻量 |
| **ORM** | Drizzle ORM 0.38.x | 타입 안전, 가볍고 학습 곡선 낮음, PostgreSQL 최적화 |
| **Database** | PostgreSQL | 신뢰성, JSON 지원, 로컬(Vercel Postgres) 배포 용이 |
| **Validation** | Zod | 런타임 스키마 검증, TypeScript 통합 |
| **Testing** | Jest + React Testing Library | 단위/통합 테스트, 컴포넌트 테스트 |
| **Deployment** | Vercel | Next.js 네이티브 지원, Postgres 통합 |

### 5.2 아키텍처

```
tika/
├── app/               # Next.js App Router (백엔드 진입점)
│   └── api/          # Route Handlers
├── src/
│   ├── server/       # 백엔드 로직 (Services, DB)
│   ├── client/       # 프런트엔드 로직 (Components, Hooks)
│   └── shared/       # 공유 타입, Zod 스키마, 상수
└── docs/             # 프로젝트 문서
```

### 5.3 경로 별칭

| 별칭 | 경로 |
|------|------|
| `@/` | `src/` |
| `@/app/` | `app/` |
| `@/shared/` | `src/shared/` |
| `@/server/` | `src/server/` |
| `@/client/` | `src/client/` |

> **레이아웃 변경**: Backlog를 좌측 사이드바 고정 + 우측에 TODO / In Progress / Done 3컬럼 보드

> - 우측: TODO → In Progress → Done 순서의 Swimlane

### 6.2 티켓 카드 구조

```
┌───────────────────────────────────┐
│ 🎯 [제목]                        │
│                                   │
│ 📅 2026-08-01 ~ 2026-08-05       │
│                                   │
│ 🟢 LOW  🔵 MEDIUM  🔴 HIGH       │
│                          [✏️] [🗑️]│
└───────────────────────────────────┘
```

> 우선순위 시각 표현: LOW(회색), MEDIUM(파랑), HIGH(빨강)

### 6.3 반응형 전략

| 화면 너비 | 레이아웃 |
|-----------|---------|
| Desktop (≥1024px) | 좌측 Backlog 사이드바 + 우측 3컬럼 |
| Tablet (768px~1023px) | 좌측 Backlog 사이드바 + 우측 2컬럼 (스크롤) |
| Mobile (<768px) | 1컬럼, 탭으로 컬럼 전환 |
